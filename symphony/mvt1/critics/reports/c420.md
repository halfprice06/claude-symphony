## Findings

The movement's state is final. Movement II and the scherzo stopped at v400. The finale (v364) last checked itself against movement I v411. A change to anything they quote could no longer be followed in those movements. Findings 1–3 are release items. Findings 4–7 are checks. Finding 8 is a judgement that keeps the score as it is.

### 1. The score still prints "draft v420" (applied)

Page 2's subsubtitle reads "Full score in C — draft v420". c200 set the release form, "v221, 12 October 2026", and score.ly line 7 still carries that comment. The draft stamp came back for the series as a cycle marker, and c355 left an open item to remove it "at the release v421". MOLA PDF 6 asks for a print or revision date on the score, not a working label. The scherzo's release copy uses the same form ("— v400, 26 October 2026").

Fix (score.ly, header):
```lilypond
subsubtitle = \markup \center-column { "Full score in C — v421, 27 October 2026" \small "Contrabassoon and double basses sound an octave lower than written" }
```
Applied in the scratch copy. If the release date is not 27 October, the composer should set the real date. The parts print no version, so they do not change.

### 2. The front page gives no total duration (applied)

MOLA PDF 6: "an approximate duration given for each movement and a total duration for the work". The front page says only "c. 7½ minutes (movement I)". The four movements' MIDI timings in the coherence files are I 7:10 (430.5 s, v420), II 5:45, III 4:36 and IV 7:02, which comes to 24:33. The total also shows the arc's proportions: the outer movements weigh the same, and the inner ones are shorter.

Fix (score.ly, front matter):
```lilypond
\line { \bold "Duration" " c. 7½ minutes (movement I); the symphony c. 25 minutes" }
```
Applied. The front page still fits on one page, and the score is still 18 pages.

### 3. Section-length check for build.sh (c419's open item; tool tested, not applied to tools/)

c419 found that a stray `%` cut four timpani bars and the score build did not notice. I wrote `/tmp/critic-420/tools/lencheck.py`. For every section variable it compares `ly:music-length` with sections.txt, once with the `part` material removed and once with the `score` material removed. On v420 every variable matches in both tag sets. A test copy with one timpani bar deleted in tOne gives `MISMATCH score tOneTimp 17 … 18` and exit code 1.

Fix: copy the script to tools/ and add one line to build.sh after assemble.py:
```bash
python3 -I "$TOOLS/lencheck.py" . >> build-warnings.txt || true
```
Any mismatch then shows as a build warning. I did not write it under tools/ because my task allows writing only to the scratch folder and the report.

### 8. The arc needs no musical change (judgement; keep)

The three late changes since the finale's last check all strengthen links the other movements rely on:
- **166 (c418).** The horns' p resolution keeps the C-major cadence soft. The Picardy third keeps its power for 182 and the forte C major for IV 223 (A&S PDF 391).
- **173–174 (c400).** The cor anglais's D♭5 held into the 6/4 is the textbook N6 – 6/4 – V (A&S PDF 483–484, Ex. 28-2c), the progression the finale completes to I at its 219–223.
- **Bar 4 (c419).** The timpani fade makes the opening motto die away as the coda's does at 179–182 (R-K PDF 130; Casanelles PDF 276), so the frame is matched.

The key plan still enlarges the motto's ♭6–5 and ♭2–1 into the A♭ climaxes and movement II's key (A&S PDF 600–601). I considered adding a hint of the finale's F1 or F2, or the scherzo's trio tune, and reject it as c260 and c330 did. The seeds that exist (12, 37, 78–79, 106, 108, 179–180) are recorded and answered. A new hint in a movement the others can no longer read would go unanswered.
