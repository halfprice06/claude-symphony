## Findings

Findings 1–3 are the layout question. I applied all three in /tmp/critic-260/work. Findings 4–6 check the joins and shared ideas; they need no change.

### 1. Parts: print bar ranges over multi-bar rests (applied)

**Problem.** The parts print only the count over each multi-bar rest ("8", "12"). Movement I's v266 now prints the bar range as well.

**Evidence.** MOLA PDF 5: "Numbering each measure should be avoided, except in the case of multi-measure rests, where measure number ranges are helpful (e.g., '27–117')." The ranges help most in a movement that begins with a tied chord from the movement before: the flute 2 player counts six bars of a link that has no wind music before the horn solo.

**Fix (genparts.py, after the c255 beam block).**
```
#(define (mmr-range-stencil grob)
   (let* ((base (ly:text-interface::print grob))
          (lc (ly:spanner-bound grob LEFT)) (rc (ly:spanner-bound grob RIGHT))
          (ll (ly:grob-property lc 'rhythmic-location #f)) (rl (ly:grob-property rc 'rhythmic-location #f)))
     (if (and (ly:stencil? base) (pair? ll) (pair? rl) (> (- (car rl) (car ll)) 1))
         (ly:stencil-combine-at-edge (ly:stencil-aligned-to base X CENTER) Y UP
           (ly:stencil-aligned-to (grob-interpret-markup grob
             (markup #:fontsize -4 #:normal-text (format #f "~a–~a" (car ll) (- (car rl) 1)))) X CENTER) 0.3)
         base)))
\layout { \context { \Staff \override MultiMeasureRestNumber.stencil = #mmr-range-stencil } }
```
The range is read from the rest's bounding columns, so it follows the score's bar numbers. Flute 2 now reads 1–6, 7–14, 15–22, 23–34, 35–36, 37–44, 45–46, 48–50, 51–52, 53–58, 65–70, 71–77, 81–82, 83–88, 89–90. Single-bar rests get no range.

The ranges added height to the viola part, which went to two pages. In the viola's bookpart the system padding goes from 0.5 to 0.25:
```
pc = "\\paper { system-system-spacing.padding = #0.25 } " if v == 'vla' else ""
```
With that change the viola part fits on one page again. Its systems are where v260 had them, and the only marks that moved are the new ranges. I tried `page-count = 1` first and rejected it because it gives "too few pages" warnings.

### 2. Score: number page 1 (applied)

**Problem.** Page 1 has no page number (LilyPond's default); pages 2–8 are numbered. Movement I's v266 numbers its front page 1.

**Evidence.** MOLA PDF 7: "Right-hand pages must be odd-numbered in the upper right corner." Page 1 is a right-hand page. Movement II has no separate front-matter page (its title block sits over the first system), so the same rule gives it "1" over the music.

**Fix (score.ly, \paper):** `print-first-page-number = ##t`. The score stays 8 pages, every system break is unchanged, and the number does not touch the title.

### 3. Score: horn short names "in F", as movement I (applied)

**Problem.** From page 2 on, the horn staves read "Hn. 1·2 / (F)". Movement I's v266 reads "Hn. 1·2 / in F", and score.ly's own c135 comment cites MOLA Example 2 for this form.

**Evidence.** MOLA PDF 9, Example 2 (rendered): "Cl. 1, 2 (B♭)", "Bass Cl. (B♭)", "Hn. 1, 2 in F", "Hn. 3, 4 in F". The clarinets ("Cl. 1·2 / (B♭)", "B.cl. / (B♭)") already match it.

### 4. Join from movement I holds; the reading supports it as written (no change)

**Bars 1–6.** I checked against movement I v261, since v266 changed layout only. Movement I's last bar has Vln I C5 ("sul D" since its v252), Vln II G4, violas E4, cellos C3 and Hn 3 C4 with \laissezVibrer, ppp, "attacca". Movement II continues all five with \repeatTie at ppp, Vln I "(sul D)" to bar 4. The timpani label reads "G, A♭, C, E♭ (as in movement I)", which is movement I's final tuning.

**Reading.** Ex. 26-4 (PDF 446) is a modulation from C to A♭, and PDF 443 explains why A♭ is close to C even though C major is not one of its chords: A♭ is VI of C minor and relates to C major through mixture. Movement I sets up exactly this by ending its C-minor movement on a C-major chord. Movement II then follows PDF 445's rule for arrival. The melody keeps C5, which is 3̂ of the new key. The bass reaches A♭ on the downbeat of bar 2, which gives the rhythmic resolution. The strong dominant comes later (8 b3, 13–14), as PDF 445 says it must. Nothing to change.

### 5. The symphony's key plan follows the large-scale plans of §12 and §15; keep the last chord plain (no change)

**Reading.** PDF 452–454 (Ex. 26-13, 26-14): tonicized VI leads down in thirds toward IV, and over a large span the plan I–VI–IV–V–I has its IV going to V "through an augmented 6th chord" (K. 488). PDF 456 §15: when V returns it is prepared by II or IV.

**Symphony.** C (I) – A♭ (II) – E = F♭ (III) – C (IV) falls by major thirds, in the same order as Ex. 26-14's descending arpeggio. The finale's first chord is a German sixth built on A♭ (finale.md, Opening), which resolves to V of C at its bar 2. So movement II's key comes back as the augmented sixth that leads to the symphony's only structural dominant. This is the reason c250 protected II's last chord as a plain A♭ triad (A♭1 A♭2 E♭3 A♭3 E♭4 A♭4 C5). The reading confirms that choice. An added sixth or seventh at 89–92 would anticipate the finale's chord. The F♭ preparations of E inside II (5, 21, 62, 78, 80, 88) work like Ex. 26-7's foreshadowing B♮–C (PDF 448). No change.
