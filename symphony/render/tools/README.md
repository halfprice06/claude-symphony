# Render measurement toolkit

Written by critic 0 (2026-10-09). Python 3 with numpy, scipy, mido, matplotlib; ffmpeg, fluidsynth and lilypond on PATH.
All scripts take absolute or relative paths; run them from any folder (run from `/tmp` if the FUSE mount
makes the current folder disappear). Results go wherever `--out` says; critics put them in `critics/cNN/`.
Never write rendered WAV stems into `/mnt/project-files` (they are large); the stem tool uses `/tmp` by default.

| script | what it measures | typical call |
|---|---|---|
| `measure.py` | one audio file: EBU R128 (ffmpeg ebur128: I, LRA, true peak) plus our own BS.1770 momentary/short-term series; short-term percentiles; sample peak, clipped samples, crest factor; noise floor; long-term average spectrum (1/3 octave), band shares, spectral slope; brightness against loudness (centroid slope, loud-minus-soft spectrum); stereo (L/R correlation overall and per band, side/mid, pan spread, pan histogram); decay after sharp cut-offs found in the audio (comparable between renders and recordings); with `--midi`: loudness per bar against the printed dynamic (from velocities), decay after the final note-off and after every silence in the score, onset lag. Plots: spectrogram, loudness with bar loudness and velocity, LTAS, final decay. | `python3 tools/measure.py rNN/out.mp3 --midi rNN/<the MIDI that was rendered> --out critics/cNN/rNN` |
| `compare.py` | table (markdown) of several `measure.py` folders and an overlay of LTAS and short-term loudness distributions | `python3 tools/compare.py critics/cNN/rNN critics/c00/ref_brahms1_i_musopen ... --md x.md --png x.png` |
| `score_events.py` | compiles a scratch copy of the v120 LilyPond score with `ly/eventlog.ily` (an engraver that logs every note and post-event) and matches each printed note to the MIDI: staff, voice, bar, beat, notated length (ties merged), printed dynamic in force, hairpin, articulations (staccato, accent, tenuto, marcato, fermata, tremolo32/16), slur position (start/in/end), technique (pizz, sul tasto), and the MIDI note it became (track, on/off ticks, length, velocity, seconds). Summary: how the MIDI realises each articulation (length ratio, velocity change). Never touches `mvt1/`. | `python3 tools/score_events.py --midi rNN/<midi> --out critics/cNN/notes.csv --summary critics/cNN/articulation_midi.json` (add `--events <events.tsv>` to skip the 30 s LilyPond run) |
| `stems.py` | renders one stem per staff (tempo track + that staff's tracks) with the given render command, 4 in parallel, and measures per stem: loudness while sounding, level per printed dynamic and dB per dynamic step, pan, L/R correlation, centroid; articulation audio metrics per class (attack time on clean onsets, level at 75 % of the notated length, audible length to -20 dB, tremolo modulation rate, accent peak boost, level dip at slurred vs detached note boundaries); blend: loudest-minus-second stem per bar, which stem is loudest, balance inversions (a stem marked softer that is >3 dB louder than a stem marked louder), family level per dynamic. | `python3 tools/stems.py --midi rNN/<midi> --notes critics/cNN/notes.csv --out critics/cNN/stems --render '<command with {midi} and {wav}>'` |
| `sfcal.py` | soundfont calibration: each GM program, one note at velocities 32-127: level, level range, spectral centroid and whether the sound gets brighter with velocity | `python3 tools/sfcal.py --sf2 assets/sf2/X.sf2 --out critics/cNN/sfcal_X` |
| `rtk.py` | shared library (decoding, K-weighting, loudness, LRA, spectra, stereo, decay fits, MIDI tempo map and bars) | imported |

## Conventions and caveats
- Loudness values are LUFS (K-weighted). K-weighting lowers the reading of low instruments (basses, tuba, contrabassoon) by a few dB compared with what a level meter without weighting shows; compare a stem with its own history or with stems in the same register.
- `stems.py` needs a render command that applies a fixed gain to every stem. If an actor's pipeline normalises loudness, the stem command must skip that step; otherwise the per-stem levels are meaningless. If the pipeline mixes separately rendered stems, pass the per-stem part of the chain (e.g. a script taking `{midi}` and writing `{wav}` with the same gain, pan and reverb send the mix uses).
- "Printed dynamic" in `stems.py` comes from the LilyPond dynamics (via `score_events.py`), not from velocities; in `measure.py --midi` it is inferred from the bar's maximum velocity using v120's volume table (ppp 0.25 ... fff 1.0 x 127).
- Articulation audio metrics are medians over notes that are not masked by other notes of the same stem; `n` says how many notes were usable. Attack times are only computed for clean onsets (stem at least 10 dB quieter 20 ms before the note).
- Decay after cut-offs: `cutoff_decays` finds sharp ensemble stops in the audio alone; `tails.final` uses the MIDI's last note-off for renders and an automatic estimate for recordings (unreliable when a recording is faded or edited; the Brahms 1 value is wrong for that reason).
- Times in `measure.py --midi` assume the audio starts at MIDI time 0 (true for FluidSynth); use `--offset` otherwise.
