# Finale mockup: lessons learned

Lessons from this movement that would help mock up a different score with this library and pipeline, appended by actors (one short dated bullet each under a topic heading). Read mockup-kit/LEARNINGS.md and symphony/mvt1/reaper-v621/loop/LEARNINGS.md first; record here where the Finale differs or adds.

## Port (c00)

After any repeat-rule change, scan parts.json for legato-row notes with no overlapping note before them and compare with the previous cycle.
- 2026-11-07 (c02): Sus MAX re-attacks with a 0.06 s gap at G2 in the cellos (f-ff, 168 qpm) still dipped only about 2 dB (broadband, 10 ms); the basses with a -5 dB / 0.08 s volume dip measured 7 dB, and bassoons with the horn re-tongue values (0.10 s gap, 12 CC fall) 6 dB (from 4). ## Rendering (c05)
- 2026-11-08 (c05): `render_cycle.py`'s settle gate (three readings 10 s apart without 50 MB of growth) passed at 30 GB on a slow reload (about 0.4 GB/min from the sample drive) while the project needs 45 GB. ## Mix tooling (c06, EastWest template)
- 2026-11-08 (c06): a ReaEQ state can be written with `TrackFX_SetNamedConfigParm(fx, "vst_chunk", b64)` where b64 is only the plugin data of the .RPP block (the base64 lines between REAPER's 60-byte header line and the 15-byte "Program 1" footer): int 33, int band count, then per band int type (0 low shelf, 1 high shelf, 3 low pass, 4 high pass, 8 band), int enabled, double Hz, double linear gain, double bandwidth in octaves, one byte 1, then a 32-byte trailer. Any band list can be built on that layout; read-back of type, Hz and gain matched on all 29 tracks.
- 2026-11-08 (c06): an FX renamed with the "renamed_name" config parameter reports that name from `TrackFX_GetFXName`, so a "delete every ReaEQ" loop that matches on "ReaEQ" skips it; check "renamed_name" as well to be sure.
- 2026-11-08 (c06): return tracks with EW Spaces II are best created by pasting the template's verbatim `<FXCHAIN>` block into the new track's state chunk (`SetTrackStateChunk`); on an existing return replace only the FXCHAIN block, because the receives (AUXRECV) live in the receiving track's chunk. Read back the Spaces II vst_chunk JSON (presetName, delay, impulseA, irSetup.endPos) to confirm the state.
- 2026-11-08 (c06): four Spaces II return tracks (true-stereo 2.6-3.4 s IRs) and Opus's own hall removed from all 31 instances left REAPER's settled footprint at 44 GB (c05 45-46 GB with the Opus hall and crash Close mic).

## Measurement: brass accent brightness (c08)
- 2026-11-08 (c08): rejected with numbers: the "master's 2-5 kHz jump at brass accents" target (p90 under +2 dB; first 80 ms minus the 200 ms before) measures entries after rests and tutti downbeats, not bright attacks. On the c07 master (98 accents): jump p90 5.2 dB, but the same jump at 0.25-1.5 kHz rose with it (tilt jump p90 3.6, median +0.1 dB); on the 59 accents where brass was already sounding (brass stems' 2-5 kHz in the 200 ms before within 6 dB of their body) p90 -1.9 dB; front minus body (0-80 vs 100-350 ms) median -8.2, p90 -3.7 dB. Use the tilt jump (target p90 under +3), the jump on sounding brass, and front minus body.

## Dynamics (c08)
- 2026-11-08 (c08): a held-decrescendo volume step released at the next onset undoes a subito: at a "sub. p" after two held decrescendos the winds stepped up 9 dB and the master did not drop. Holding the step through the subito to the next crescendo (HELD_DECRESC_CARRY) made the winds fall 4 dB and the master 1.7 dB, but the strings still rose 2.4 dB: the subito also needs the CC drop to win over the new note's attack on the string rows.

## Dynamics: fp / sfp attacks and led notes (c09)
- 2026-11-08 (c09): a hairpin printed on the same onset as an fp / sfp ("sfp <") adds (q, level) points after the mark's own points, and the curve keeps the later point at a shared onset, so the value at the mark was the p and the attack rose only 0.02 qn later. Every led note holds the CC of its score onset from its moved note-on, so 23 of 24 sfp notes started on the p layer and swelled into the sf (c08 strings: sf peak 4-5 dB under the ff before, 0.2-0.3 s late). Write the attack as a step at the mark and start the hairpin where the attack has fallen; check the CC at each moved note-on in parts.json, not only the curve.
- 2026-11-08 (c09): a printed mark entered twice in the event list (LilyPond writes some dynamics twice) runs a mark rule twice; any rule that appends (q, level) points must give the same result when it runs twice.

## Mix: the template's halls and the volume envelope (c09)
- 2026-11-08 (c09, critic C's measurement on c08): with the Opus hall off and the EW returns fed by post-fader sends, the track volume envelope sits before the hall: at an sfp the dry stems fell 7.5 dB in 0.27 s while the four returns fell 0.3 dB. Fast volume-envelope drops under a sounding chord no longer cut the tail; S3's "CC only" rule applied to the Opus-internal hall.
