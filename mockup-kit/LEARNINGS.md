# Kit learnings: orchestral mockups with REAPER + EastWest Hollywood Orchestra Opus Edition

Curated 2026-10-11 from the movement II mockup loop (cycles c00-c08 rendered and measured; c08's own render measured by the c08 actor, not yet by critics). Sources: `symphony/mvt2/reaper/README.md`, `loop/BRIEF.md`, `loop/HISTORY.md`, `loop/LEARNINGS.md`, `loop/ONE_TIME.withdrawn.md`, `cycles/c01-c08/CHANGES.md`, `cycles/c01-c08/reports/*.md`, `tools/*.py`, `build/mix.json`, `build/roles.json`, `build/note_trims.json`, `build/pitch_trims.json`, `build/early_fills.json`, `build/entry_leads.json`, `opus/ (installed at ~/.rpr-bridge/libs/ew_ho/)`.

This file keeps only lessons that apply to another score. Evidence is in parentheses: cycle and measured numbers. "Unverified" means implemented or proposed but not confirmed by a measured render. "Inferred" means reasoned from data or manuals, not measured directly.

Library: Hollywood Orchestra Opus Edition Diamond (KS Master patches for solo winds and brass and string sections, Harp, Timpani), on an external USB/exFAT drive. Machine: a 96 GB Mac. Pipeline: LilyPond score -> MIDI + event list -> `parts.json` -> Lua jobs through the `~/.rpr-bridge` file bridge -> REAPER, one Opus instance per track (27 tracks).

## 1. Loading Opus patches by script

- Patch loading is scriptable. Opus's VST3 state is gzip-compressed JSON (a `Performance` with a `zones` list); write it with `TrackFX_SetNamedConfigParm(tr, 0, "vst_chunk", base64)` (c00).
- An `.oib` patch file is a 20-byte header followed by zlib/gzip JSON holding one `Instrument`; the plugin state is a 28-byte header, the gzip JSON, and a tail (`opus_state.py`: `HDR = 28`, `load_oib` reads from byte 20).
- Put the patch into a zone as `{"class": "InstrumentZone", "keyMin": 0, "keyMax": 127, "velMin": 1, "velMax": 127, "octave": 0, "groupIndex": 0, "instrument": <oib JSON>}` (c00).
- The first 4 bytes of the state (little-endian u32) must equal the total blob length minus 16, or Opus truncates the JSON (c00).
- A zone that holds only a locator path, without the full instrument JSON, crashes Opus (c00).
- Everything a patch does is editable in that JSON before loading: articulation rows, mic columns and volumes, per-mic pans, mixer inserts (reverb, sends), script filters (EWSO, RTKiller, ConSordino, FingerPosition), and the starting keyswitch (c01-c05).
- Read keyswitch maps and sample ranges from the `.oib` files, not from screenshots or memory (`opus/dump_ks.py`, `ks_maps.json`). The Harp Maestro range error (section 9) was found by reading every group's keyMin/keyMax from the file (c01).
- Any state change (mics, reverb, rows, pans inside Opus) needs the patch reloaded; a cache that reuses old state files hides the change. The c00 build reused existing `.b64` files, so state edits had no effect until the cache check was removed (c01 critic C).
- Write gzip with `mtime=0` so a generated state is byte-for-byte reproducible. The build can then compare the new state with the last one written and skip the patch reload when they are equal (c07, `build_reaper.py --midi-only`). Reloading a patch is expensive in memory (section 11).

## 2. KS Master patches: articulation rows and keyswitches

- A KS Master loads only its first rows by default: the string KS Masters load six (Sus MAX, Sus Marc LITE, Leg Slur MAX, Staccatissimo, Stac On Bow, Marc Shrt). Keyswitches to unloaded rows are ignored and the current articulation keeps playing (c02: pizz. notes measured as bowed sustains, time to peak 600-720 ms, decay 1-1.7 dB).
- To load a row, set `layerMatrix.rows[i].loaded = true` and `active = true`, and on the matching `articulations.trigger` entry set `useKey = true` and a `triggerName` (c02). After this, pizz. decayed 10-16 dB within 400 ms of the peak and onsets rose in 0-10 ms (c02, c03).
- Match row names case-insensitively: the cor anglais row is "Sus Max", not "Sus MAX" (c02).
- Opus names keys with C0 = MIDI 24 (`triggerName = NOTE[key % 12] + str(key // 12 - 2)`). String KS Master keyswitches start at 24; examples: 1st Violins Leg BC MAX 48, Slur Runs 42; Celli KS Master keyswitches sit at 80-90; Harp KS Master keyswitches are 21-35 (`ks_maps.json`).
- Setting `articulations.currentKeySwitch` in the state does not reliably select the first articulation. Trombone 1's first two Sus Accent notes (selected only by state) measured -8.8 / -8.6 dB attack brightness against +5.6 dB for the same articulation reached by a keyswitch (c03). Send every track's first keyswitch as a MIDI note in a silent pre-roll bar (section 11; c06). The `currentTrigger` and `lastArticulationId` fields were not tested.
- Keyswitch notes of velocity 1 and 0.03 qn length work (c00-c08).
- Put keyswitches and CC15 changes in the preceding rest (rest start + min(0.5 qn, 25% of the rest)), not on the note onset. In c00, six of eight 535-650 ms late entries coincided with a CC15 change on the note (c01 critic A; correlation only, cause not isolated).
- With a rest before the note, a keyswitch lead of 55 ms or more was always enough (c03: median lead 69 ms, minimum 55 ms). A re-tongue keyswitch 0.012 qn before the note worked inside a wind portato passage (c07). Unverified: whether a 3 ms lead fails.
- Do not send a keyswitch while a note on a legato patch is still sounding; end the legato note 0.01 qn before the keyswitch (c05 guard, 6 notes in this score). Every held-note-to-tremolo check passed in the renders made after the guard without memory pressure (c05, c07, c08), but the guard's effect was not isolated from the session restart (section 11).

## 3. Controllers in Hollywood Orchestra

- CC11 (Expression) crossfades the dynamic layers and also sets volume (HO manual 2.1.3). Use it as the dynamic control; do not use CC1 for dynamics.
- CC1 (Mod wheel) crossfades the non-vibrato and vibrato sustain layers in the MAX patches (read from `OB Leg Slur MAX.oib`, `OB KS Master.oib`; c04 critic C).
- CC7 is MIDI volume; its curve is not documented and is shallower than 40·log10 at low values (c02: a CC7 change from 16 to 13 measured 0.6-1.5 dB instead of the intended 4 dB). Prefer a REAPER volume envelope for exact dB.
- CC15 drives the Con Sordino script in the string KS Masters and in `1FH KS Master` (c02). It is a filter emulation, not muted samples, and it does not lower the level much: a muted Horn 4 stayed 5-7 dB over a muted Horn 3 (c05); a -4 dB role cut was still needed.
- CC70 is Finger Position in the string KS Masters: 0-38 FP1, 39-76 FP2, 77-114 FP3, 115-127 FP4 (HO manual pp. 92-95). Higher positions move notes to lower strings. Used for sul D/G/C (127) and sul A (20 up to MIDI 74, 127 above). Unverified: no stem difference was measured.
- Other mapped controls in the string KS Masters (`ks_maps.json`): CC5 Legato Time, CC22 True Legato mono/poly (below 64 = polyphonic, HO manual p. 91), CC64 Repetition Sustain, CC65 Portamento, CC68 Legato, CC69 Repetition, CC36 Reset RR. None of these were tested.
- Velocity: on legato targets it sets transition speed, not loudness (HO manual 2.1.1). On short articulations, harp and timpani it sets loudness.
- Velocity on the felt timpani and harp is the dynamic. Harp CC11 should be held constant, or soft notes are attenuated twice (c01: Harp Maestro measured 19 dB from pp to mp against about 7 dB for strings).

## 4. CC11 response and per-track level

- CC11 is far from linear in dB, and it flattens at the top. Within 115 sustained notes it moved the level 5.7 dB per 10 CC at CC 0-40, 3.5 at 30-60, 2.5 at 50-80 and 1.2 at 88-128; wind patches averaged 1.8 (c06 critic C). Crescendos starting at CC 72 or above grew a median 3.3 dB, those starting under 60 grew 5.9 dB (c06 critic C).
- The c02 finding that strings barely respond below CC 40 (about 1.1 dB per 14 CC inside single notes; a printed decrescendo from 34 to 22 moved the strings only -1.6 to -3.5 dB) was from a few notes and is not borne out by the c06 measurement over 115 notes. Use the volume envelope for exact fades below pp either way.
- The level per CC11 step differs by patch: fitted 0.17-0.36 dB/CC across tracks (c02: Oboe 0.175, Trombone 0.173, Vln I 0.300, Flute 0.364, Celli 0.358). Later fits: violins 0.23-0.25, violas 0.31-0.325, clarinet 0.17, clarinet 2 0.20, bass clarinet 0.26, bassoons 0.30-0.34, oboe/contrabassoon 0.19-0.22, horns 0.27-0.34 (c03, c05, c06). Balance set at one dynamic therefore drifts at another.
- Some patches jump in mid-range: from the CC 52-64 bin to the 64-80 bin, bass clarinet +10.9 dB, Flute +7.6, Clarinet 2 +7.6, celli +7.3 (c02).
- At pp-p the Basses KS Master sits 5-12 dB under the Celli KS Master at the same CC11; at f the gap is 0-3 dB (c06). Soft passages need about +3 to +5 dB on the basses (c06: Cb minus Vc over 18 soft bars, median -8.1 -> -2.6 dB).
- The top layer runs to CC 127 (FL KS Master layer ranges 0-55, 56-93, 94-127). With ff at CC 104, f to ff measured only +2.5 LU; ff at 114 and fff at 124 restored the growth (c02).
- A dynamic table that worked: ppp 22, pp 34, p 46, mp 58, mf 72, f 88, ff 114, fff 124 (c02-c08).
- A hairpin without a printed target that moves 14 CC measured a median +2.6 dB, and 38 of 95 moved less than 1.5 dB or the wrong way; targeted hairpins of more than 16 CC measured a median 7 dB (c02). Use about 22 CC for untargeted hairpins from mp or softer (c02).
- Because CC11 flattens at the top, crescendos to f or louder need a dB ramp in the volume envelope as well: +4 dB winds, +3 strings, +2 brass, rising across the hairpin (c06). Wind growth over the bar-60 crescendo went from -1..+0.7 to +1.7..+3.6 dB (c06).
- Hold that ramp until the first onset after the arrival note (cap 4 qn), then release it over 1 qn. Releasing from the arrival note itself made every f/ff arrival fall 3-6 dB in its first beat; holding it cut the falls to 1-3.6 dB and raised the climax bar 2.4 dB (c08). Do not release over 0.25 qn: that sounds like fp (c06).
- An +8 CC11 boost is about +2.5-3 dB at mid-range slopes (c01 critic B). End such boosts at the next dynamic or rest, and fade them out toward f, or they inflate climaxes (c02: celli 5-10 dB over the tune from a cantabile boost that ran 40 qn).
- Keep CC11 as the layer control and make balance corrections with level only (track volume envelope), so the timbre of each printed dynamic is kept, and the level shaping can be measured on the post-fader stems against the plan (c02-c08).
- Per-track dynamic trims: a trim that is 0 dB at p (CC 46) and reaches a set value at f (CC 88) and ff (CC 114), read from the printed dynamic curve (not from CC11, so accents do not move it), corrected the slope differences (c02-c04). Soft trims need their own anchors: ppp/pp/p (global {-2, 0, +2}) with per-track overrides; a single soft trim for all winds left the bassoons 5-9 dB under the clarinets at pp (c06). A trim that tapers linearly from the p anchor to the f anchor still adds most of the p value at mp (c07 critic B: +3.6 dB at mp from a p +5); check mp passages after setting soft trims.
- Raising ppp/pp/p by 2 dB in the volume envelope, f/ff unchanged, narrowed the loudness range from 25.4 to 23.9 LU without changing the CC11 layers (c06). A commercial recording of a Dvořák symphony movement measured 21.8 LU.
- sf from f or louder: a short spike, then fall 10 CC (not to mf) with the 0.25 qn point at spike - 4. Falling to mf from ff dropped Vln I 8.1 dB in the first beat; the new rule gave -2.8 then -2 to -3 dB per beat (c06).

## 5. Legato patches (Leg Slur MAX, Leg BC MAX)

- Legato patches are monophonic: a chord on a legato patch drops notes. Keep chords and simultaneous divisi notes on Sus patches (c00-c08: 0 chord onsets on legato patches).
- A legato transition needs overlap; 0.04 qn worked (c00-c08). Apply the overlap only inside one slur, and end the last note of a slur 0.05 qn early when a new slur starts, so the patch re-attacks (c01).
- Never overlap into the same pitch: the old note-off arrives after the new note-on and stops it (c01: dips of -18 to -33 dB; an ff oboe half note fell from -37 to -98 dB).
- A disconnected note on Leg Slur MAX plays the sustain layer (HO manual 2.1.3), so one patch can carry a whole line (c02).
- Leg BC MAX (bow-change legato) is in the 1st/2nd Violins, Violas and Celli KS Masters, not in the Basses KS Master. For connected unslurred string notes and slur-to-slur joins at mf and above it cut join dips from -8..-12 dB to -4..-5 dB (c02 -> c03). Joins inside a slur measured about -2 dB (c03).
- At pp-p, short slur-to-slur joins on the Violas Leg BC MAX dip 9-10 dB, against 4-5 dB for Leg Slur MAX joins. Keeping joins with a target under 0.8 s at CC11 52 or less on Leg Slur MAX (still overlapped, with an 8 CC bow-change notch) cut the median dip of 15 such joins from 10.2 to 6.2 dB (c08).
- Leg BC MAX targets at pp have a bump in the sample about 0.15-0.5 s after the onset (peak minus body 4-8 dB). A CC11 dip of -7 CC over that span cut it only 1-1.5 dB (c07: Vln II +7.9 -> +6.4); the bump is in the sample, so a volume-envelope dip is the next thing to try.
- Turn on legato speed: KS Masters ship with `EWSO.legato_speed_active = false` and `RTKiller.active = false`; the dedicated Leg Slur MAX patches have both true (c02). The LegatoSpeed script maps velocity 30-127 to a sample start offset of 0-4800 samples (about 100 ms).
- Measured legato lag (crossover of new-pitch over old-pitch energy, harmonics 1-4, from the MIDI onset): with velocity from the printed dynamic (41-63), strings 200-250 ms median, horns 125 ms, woodwinds 80-140 ms (c01). With legato speed on and velocity 105-120, strings 222-310 ms, horns 185-385 ms (c02, c03). Velocity 120 against 105 gained 25-80 ms (c03 critic C).
- The legato lag is deterministic (interquartile range about ±40 ms; two renders identical note for note, c03 critic C), so compensate by moving legato target notes earlier and keeping CC11/CC1/volume on score time.
- The lag depends on the source pitch: viola transitions leaving C4 crossed over 0.22-0.37 s after the onset against a 0.05 s median for every other viola transition (c06 critic A). Measure takeover per source pitch before setting one lead per family; an extra 0.10 s for that source pitch was added (c06, not measured separately).
- Leads that worked: strings 0.17 s with velocity 124 (Violins II and Violas 0.20 s), brass 0.10 s with velocity 124. Result: string crossover medians 250-275 -> 50-85 ms, horns 190-200 -> 85-108 ms (c03); Vln II +0.053 -> +0.023 s, Vla +0.060 -> +0.043 s with the 0.20 s lead (c07). Woodwinds: oboe/bassoon 0.06 s, bass clarinet 0.05 s, cor anglais 0.08 s, flute/clarinet 0.03 s (c03, c04).
- Convert leads from seconds to qn on the real tempo map going back from the onset, caesuras included, not at the onset's own tempo: after a caesura or a slow rit. step the onset-tempo conversion made 0.17 s leads 0.25-0.30 s long (c07).
- Cap the lead at 0.45 of the previous note's length and move the previous note's end with it so the overlap survives (c03).
- In soft codas, legato targets at velocity 124 can be too fast and present; velocity 90 for soft (CC11 40 or less) string legato targets was used (c08; effect not measured separately).
- Fast slurred notes under 0.25 s smear on legato patches (transitions of 160-320 ms; a viola sextuplet figure ran 230 ms behind, c03 critic C). Sus MAX with 0.03 qn overlap was used instead; a residual 90-120 ms lag remained (c03). The Violins KS Masters have Slur Runs rows (keys 42/43) that were not tried.
- Measure note lengths for articulation choice on the tempo map without caesuras or other expressive time, or a fermata-like slowing turns a short note into a legato target (c05).

## 6. Soft entries, re-attacks, sags and sample blooms

- Soft sustained string and brass entries reach level slowly: arrival (within 6 dB of the early peak) 300-1010 ms for pp/p strings, 355-495 ms for soft horn/trombone/tuba entries, against 60-150 ms for winds at the same moments (c03 critic C). The times repeat across renders, so they are sample attack, not streaming.
- Moving soft entries earlier (strings 0.12 s at CC11 <= 50 / 0.06 s above; brass 0.10 / 0.05 s; bassoons 0.06 s) with CC11 held at the entry's own level from the moved onset brought string arrival medians to Vln I 310, Vln II 488, Vla 230, Vc 100 ms (c03).
- Larger per-onset leads (extra seconds per entry from a measured lag minus 0.05 s, total capped at 0.30 s) helped loud and mid entries but not every pp string entry: Vln I qn 171 0.38 -> 0.20 s, Vc 0 0.36 -> 0.12, Cl1 0.17 -> -0.04, but Vln II qn 42 0.24 -> 0.45 and Vla 54 0.33 -> 0.54 (c07). Inferred: the soft first-note sample starts quietly and grows over 0.3-0.4 s, so extra lead only makes the quiet part earlier. Measure the shape of the first 0.3 s before adding lead to a pp entry.
- Solo wind and horn legato targets (Flute, Oboe, English Horn, Solo Horn KS Masters) often sag 5-12 dB for the first 0.3 s at flat CC11 and then swell; the shape repeats from render to render (c08 critic A, 35 notes). A volume-envelope lift (0 at the onset, +dB by +0.05 s, held to +0.35 s, gone by +0.6 s; dB = sag - 2, cap 8) brought 30 such notes from 7-10 dB to 2-4 dB (c08).
- A same-pitch re-attack on Leg Slur MAX at pp takes 300+ ms to reach level, leaving 7-15 dB holes in the stem (c03 critic A). Merge same-pitch repeats in legato string lines into one note with a CC11 notch (10 CC portato, 14 CC bow change, 8 CC at CC11 <= 40) (c03, c04). Printed bow marks inside a held note get the same notch (14 CC above CC 40, 6 at pp and softer); Vln I dipped about 2 dB and recovered within 0.125 qn (c06).
- Long notes on some MAX sustain layers swell 8-17 dB at constant CC11: Oboe F5, cor anglais A4, Flute B♭6 (c02). Soft unslurred Sus MAX string chords bloom 6-9 dB inside each note (c02). A soft re-attack on Leg Slur MAX after a gap rose 14 dB over 2.5 qn (c04 critic C). These are per-sample, so correct them per note or per pitch (section 13).
- Fixes that worked: per-note level trims keyed by onset (0 dB at the onset to the full trim at onset + 0.6 s), found by a residual scan against the track's CC11 fit (c03: notes over +5 dB); a volume ramp of 0 to -4.5 dB over 2 qn on soft re-attacks (c04). Keying trims by pitch and minimum length hit the wrong notes (c03 critic B).
- Wind portato (tenuto inside a slur) on a legato patch re-starts on the slow non-legato layer: Flute 2 bloomed 0.6 s after the beat (c04 critic A). Re-tongued on Sus at ff it left 6-12 dB holes at each note (c06 critic A). What worked best: a tenuto to a new pitch as a Leg Slur target (velocity 100, 10 CC notch); a repeated pitch re-tongued on Sus with the previous note ending 0.01 qn early and a 0.04 s lead; unslurred tenutos crossfaded 0.03 qn. Join dips went 5.7-8.0 -> 4.1-5.2 dB (c07). A flute Leg Slur transition up to F6 still dipped 10 dB inside the transition itself.
- A string note that follows a legato note with no rest but switches to Sus MAX (e.g. a div. chord) re-attacks slowly like an entry. Giving it the entry lead, CC11 held at the entry level and velocity 105 or more, and ending the old notes 0.03 qn after the new score onset, cut viola joins of 6 dB or more from 8 to 2 (c06, c07).

## 7. Other string and wind articulations

- Pizzicato (after loading the row): on time in every render made without memory pressure (c02, c03, c05, c07, c08: 0.00-0.04 s); decay 10-16 dB at 400 ms (c02, c03).
- Tremolo after a held note on another articulation: the 9-26 dB holes at the arrival (c04) were render timing, not CC11 and not the patch. With identical MIDI, a fresh session gave dips of 0.5-6.8 dB (c05), a session under memory pressure gave 20-30 dB holes with the tremolo 0.2 s late (c06), and fresh sessions passed again (c07, c08). The c04 hypothesis that tremolo does not sound at high CC11 was not needed; separate tremolo tracks were not needed.
- Tremolo chords on a section patch are much louder than single notes: Vln II 2-note tremolo +8.2 dB over its single-note fit (c03 critic B).
- Accents: keep `Sus Accent MAX` for f and louder; for softer accents add +8 CC11 decaying over 0.3 qn and velocity +10 (c01). A keyswitched accent measured +3 to +4 dB over the previous bar with +4 to +6 dB attack brightness (c03).
- sf: a short CC11 spike above the current level (+8 from f or louder, held 0.25 qn; +12 from softer levels) and velocity +15 (c02-c04); after the spike see section 4. If a decrescendo starts at the sf, start the hairpin after the spike, not before it (c02 critic B).
- Tenuto arrivals at f or louder under "molto sostenuto": hold CC11 at the arrival value to the note end instead of letting the tenuto bump decay (c08; part of the 1-3.6 dB arrival falls in section 4).
- Breath marks: end the note before at `min(0.25 qn, 20%)` early (c01). Caesuras as tempo-map pauses: +0.22 s and +0.15 s before tutti arrivals (c04), 0.08-0.12 s at solo breath marks and phrase seams (c08). Every tempo-map change needs all items recreated, not the patches (section 15).
- Clarinets on Sus Non Vib were kept throughout; their measured vibrato was 1-8 cents, as expected (c04 critic C).
- A "solo" marking on a string section part still sounds like a section; an +8 CC11 solo boost put Vln I 5.6 dB over the oboe solo that answers it. Without the boost, with CC1 +10 and a -3 dB role, it was 1.9 dB under (c08). The real fix is a DIV A half-section patch on its own track, not tried because of memory (section 11).

## 8. Divisi, double stops and shared patches

- Every note of a chord on a section patch is a full-section sample: 2-note chords measured +1.8 to +2.0 dB over single notes on Sus MAX/Flautando, so a divisi passage is about twice as thick as written (c03 critic B). A level cut of -10·log10(k) dB under "div." and -1.5 dB for "non div." double stops, plus -3 dB for tremolo chords, fixed the measured cases (c03 -> c04).
- The Divisi folders hold DIV A / DIV B KS Masters (half sections) for 1st/2nd Violins, Violas and Celli. Not tried; it is the route for divisi lines that need legato and for a section "solo" when no solo-string library is installed. Each one is another Opus instance and adds sample memory (section 11).
- Two tracks on the same patch file playing the same pitch together render the identical sample: correlation 0.999, a +6.5 dB coherent sum (Horns 1+2), or partial cancellation at correlation -0.86 (two clarinets: the sum was quieter than one) (c04 critic A). Drop the copy and give the kept note +10·log10(n) dB (c04). A recorded a2 patch (2FH KS Master) is the alternative (not tried).

## 9. Harp

- `Harp Maestro.oib` has no samples below MIDI 48: 79 of 175 notes in a normal harp part were silent (c01). `Harp Sus RR.oib`, `Harp Pluck Long.oib` and `Harp Thumb Pick.oib` cover 24-103 (c01).
- The Harp KS Master reaches only down to 36, and its keyswitches (21-35) overlap the harp's low notes (c00).
- Harp Maestro loads only the Close mic (c01).
- `Harp Harmonics.oib` (range 48-96) takes sounding pitch: notes measured 311 Hz and 622 Hz as written in sounding pitch (c01). Its level is about 0.55 dB per velocity step around v58-76 (c08: v76 -47.7 dB, v58 -57.7 dB).
- Harp dynamics by velocity with CC11 constant at 110 worked: pp 52, p 64, mp 76, mf 90, f 100 (c01-c04). The harp rings after note-off and decays only 2-4 dB in 0.4 s (c03).
- Rolled chords: play from the lowest note up, 40 ms per note at mp or softer and 30 ms louder, top note +4 velocity (c04). A LilyPond extraction must listen for `arpeggio-event` explicitly; it is not an articulation event (c04 critic A).
- The Harmonics patch images further left than the Harp patch at the same pan settings (c05 critic C: R-L -9.5 vs -4.2 dB); match seats by measurement.

## 10. Timpani (Timpani Flt KS, felt sticks)

- The patch has no CC11; CC7 is the only level control. Velocity hardly changes roll level (c01 critic B).
- The roll articulation (Rls) is about 14 dB louder than single strokes (Lng) at the same CC7 and velocity (c01 critic B: p strokes -38 dB, p roll -24 dB).
- Strokes have a steep velocity step: velocity 41 measured -62 to -68 dB, velocity 53 -38 dB; an 8-16 dB step lies between 56 and 64 (c01, c02). Keep stroke velocity at 56 or more (pp) and 60-64 for pp/p strokes that must be heard.
- CC7 values from `127·10^(dB/40)` with roll targets ppp -36, pp -31, p -26, mp -23, mf -17, f -16, ff -11, fff -9 dB (ff/fff raised from -14/-12 in c06), and strokes at roll +20 (pp), +12 (p), +16 (above), gave usable levels after track gain -7 dB (c01-c06). Put the roll settle and soft-roll cut in the volume envelope, not CC7: -5 dB over 3 qn measured -3.6 to -3.9 dB (c02, c03), and soft rolls (p or softer) need a further -6 dB to sit under pp strings (c03).
- Hold the settle until about 0.5 qn after the roll ends or the next onset; restoring the level at the roll's last onset lifted its ring (c05: the roll at qn 271-272 then sat 8 dB under Vln I).
- The KS patch loads Close, Main and Surround mics by default (c01). Timpani take 85-100% of the master's 100-300 Hz energy when the Surround mic and a 3.3 s percussion IR are on (c01 critic C). Close 0.2 / Main 0.5 with Surround off took 7 dB out of the timpani's 125-180 Hz (c05), which contributed to a thin low-mid (section 14).
- Missing timpani strokes (-94 and -117 dB) occurred in a render made with a cold disk cache after a reboot, and were present in the next render (c04).

## 11. Memory, sample streaming and render timing

- Memory is the binding constraint for a full Opus orchestra. A freshly loaded 27-instance project holds about 49 GB in REAPER (c07, c08) on a 96 GB Mac. Every extra instance (divisi or solo tracks) and every extra mic adds to it.
- Re-setting an Opus state with `vst_chunk` on a live track does not free the old instrument's memory. Full 27-track rebuilds took one session from about 49 GB to 57 GB and a later session to 72 GB (c06, c07).
- Under memory pressure macOS compresses REAPER's idle sample memory, and a 1x offline render then starts entries late on tracks whose data did not change. c06: REAPER 57 GB with 42 GB compressed, 200 MB free, swap in use; 10 of 19 attack checks failed, every failing entry 0.2-0.3 s late, tremolo arrivals leaving 20-30 dB holes. c07 from a fresh REAPER (49 GB, 0 GB compressed), same machine and preload: 19 of 19 passed, median entry arrival 0.060 s (c06 0.102).
- The Mac froze and needed a reset during the second heavy render of one cycle (2026-10-11, c04). The cause was not measured; memory pressure is the likely cause (inferred from the 57-72 GB sessions with most of it compressed measured in c06-c07). Render once per cycle and check the data before rendering instead of rendering twice.
- Restart REAPER before rendering after any patch reloads: save, quit, reopen, and wait for loading to finish (c07: 0 GB compressed after the restart, render passed). For changes that do not touch the Opus state, replace only each track's MIDI item, volume envelope and ReaEQ and keep the instance (`build_reaper.py --midi-only`): 27 tracks in about 30 s instead of a full reload (c07).
- A large compressed figure is a warning, not a verdict. In c08 other jobs (a 5-6 GB Python job, Godot, Spotlight, about 30 GB of file cache) compressed 36 of REAPER's 49 GB after a fresh load, and the forced render still passed 19 of 19. The failing c06 session had also grown through patch reloads. Check `top -l 1 -o mem -stats pid,command,mem,cmprs` before rendering (the gate refuses above 6 GB compressed unless forced), and run the attack probe after every render either way.
- Close other memory-heavy processes before rendering (c05 critic A found two other Python processes at about 3.2 GB each during the slow c04 render; c06 had two such jobs plus Spotlight reading the internal disk at about 300 MB/s).
- Wait for Opus to finish loading samples after any load or rebuild: a render right after a full rebuild had 83 late entries; the same project 25 minutes later had 26 (c02). Rule in use: three 10 s readings of REAPER's memory in a row changing by under 50 MB. Loading takes about 12 minutes with a warm drive cache (c07) and about 25 minutes after a Mac reset, at about 1 GB per minute (30-70 MB/s) from the external drive (c08). A wait loop with a fixed cap must refuse to render if memory is still growing (cap now 2700 s), or it renders half-loaded patches (c08).
- Full-speed offline renders start notes up to 0.6 s late: several tracks at the same moment had about 0.5 s of digital silence then a full attack (c01). Render at 1x offline: woodwind late entries 20 -> 3, strings at one entry 545-575 -> 135-350 ms, brass 515 -> 170 ms (c01).
- `RENDER_1X 1` cannot be set with `GetSetProjectInfo`; edit the `.rpp` line and reopen the project (c01). `render_cycle.py` warns when the line is missing.
- Events on the very first block of an offline render can be dropped: one opening voice at -75 dB in one render, two string sections silent in another, with identical MIDI (c04, c05; c06 critic A). Put a silent pre-roll bar before the music (3 qn at 60 bpm = 3.000 s = 144000 samples at 48 kHz), send each track's first keyswitch and first value of every CC lane in it, and cut it off the master and every stem after the render, reading the time back with `TimeMap2_QNToTime` so analysis keeps the score timeline (c06: Horn 3 opening max -75.0 -> -56.2 dB). Leads of opening notes may start inside the pre-roll; set the silence-check threshold for the cut part accordingly (c07: -40 dBFS).
- Opus `PreloadSize` in `/Library/Application Support/East West/Opus/Preferences.json` (0 = Harddrive, 1 = SSD/SATA, 2 = SSD/PCIe, order from the Opus binary) was kept at 1. Setting 0 was proposed to fix late entries but not applied: the Opus manual (Audio Engine) says the Harddrive setting keeps more of each sample in RAM, and the late entries came from memory pressure, so a larger preload would add to the cause (c07). Renders at 1 from a fresh session passed every attack check (c05, c07, c08). Change it only with REAPER closed.
- An agent run under Claude Code cannot edit that Preferences.json: the permission system blocked the edit even with the user's approval in chat (c06). The user has to change it in Opus's settings.
- Separate render-engine lateness from sample attack by comparing renders: engine delays change between renders and sessions, sample-attack delays repeat exactly (c01, c03 critic C, c05-c07). Do not compensate engine delays by moving notes (c01).

## 12. Mics, reverb and panning inside Opus

- Factory mic balances differ widely between KS Masters: woodwinds Close 1.0 with Main 0.01-0.28 (Main 11-40 dB under Close), horns Close 1.35 / Main 0.44, strings Close 0.66 / Main 1.0, Basses Close 0.94 / Main 1.0, Tuba 1.0 / 1.0, Trombones Close 0.486 (c01 critic C, c05 critic C). Woodwinds then sound nearer than the strings.
- Settings used: woodwinds Close 0.5 / Main 0.8, horns 0.5 / 1.0, harp 0.6 / 1.0, strings and trombones at patch default (c01); timpani Close 0.2 / Main 0.5 (Surround off), tuba 0.45 / 1.0, basses 0.4 / 1.0 (c05). Lowering the Close mic on basses and timpani thinned 125-180 Hz (section 14).
- Mic channels to load are `layerMatrix.columns[n].loaded` plus the `mixer.channels` `sub:` channel `loaded` and `volume` (c01). Loading extra mics (e.g. Surround) adds sample memory (c05 critic C).
- Every patch carries its own reverb: a `ConvolutionReverb` on the `fx:0` channel fed by a `SendProcessor` on each mic channel. Across the KS Masters there were six different IRs and effective reverb levels from -10.6 dB (brass) to -24 dB (harp) (c01 critic C). Replace every patch's reverb insert with one copied from a single patch, set the same `fx:0` volume and `wet` everywhere, and set depth with the per-mic send level only (c01).
- Send levels that kept depth order: strings 0.25, harp 0.3, woodwinds 0.35, trombones/tuba/timpani 0.45, horns 0.5, with `wet` 2.0 (c01-c08).
- "S. Cal. Hall strings LR Rear" (the strings' factory IR) is a long hall (HO manual: 3.4 s): stems decayed with a median late slope of 3.1 s against 1.5-1.95 s in a real recording (c05 critic C). "New Hollywood Hall 2.0" (from `3BS Sus MAX.oib`, 30 ms pre-delay; ships with Opus) at fx volume 0.19 shortened the late slope to 2.5 s, but the drop 300 ms after a cutoff stayed about 10 dB against 13-17 in the recording, because the raised fx volume kept the early tail (c05). A lower fx volume (toward 0.15) was not tried.
- The patches pan their own Close channels (Cb +0.62, Vc +0.33, Bn +0.41, Vln I -0.31, etc.), and REAPER's default pan on a stereo track is a balance control; combined, the c00 mix had master coherence 0.07 at 0.8-3 kHz against 0.70 in a recording (c01 critic C). Set every seat in one place.
- Seats can be set inside Opus: on each mic channel `panLeft = seat - width`, `panRight = seat + width`, the `fx:0` reverb return centred at full width (-1 / +1), and the REAPER track at pan 0, width 1 (c05; read back from the state). Seats held (Vln I -8.0 dB R-L, Vc +4.1, Cb +5.4), and the master measured correlation 0.52 and side/mid -4.9 dB against 0.55 and -5.3 in the reference (c07 render). Melody margins at the climaxes rose 3-5 dB in the same cycle; part of that is inferred to come from the changed mono sum of the outer seats (c05).
- Moving the seat into Opus did not stop the reverb tails following the seat (c05: Vln I sustain -8.0 / tail -8.3 dB; Cb +5.4 / +6.5). Inferred: Opus's reverb send is taken after the channel pan. A REAPER volume envelope after Opus also changes the tail of notes already sounding (inferred). The fix not yet tried: turn the Opus reverb off and feed one convolution on a REAPER bus from post-FX, pre-fader sends.
- REAPER stereo pan mode (`I_PANMODE 5`, `D_PAN`, `D_WIDTH`) also placed seats correctly before c05 (c04: Vln I -8.7 dB R-L ... Cb +5.2), but it moves and narrows the in-patch reverb with the dry sound. Widths: 0.3 gave master correlation 0.76; wind 0.5, horn 0.6, others 0.5-0.6 gave 0.64 against 0.60 in the reference (c03 -> c04). Do not go below 0.3: the spaced Main pair folds to near mono (c01 critic C, inferred).

## 13. Starting levels and balance rules

- At equal CC11, the raw patches are far apart. At p (CC 46): solo winds -35 to -45 dB, string sections -46 to -53 dB, double basses -34.6 dB, harp -56 dB (c00, K-weighted). Track gains that brought every solo wind and string section to -46..-52 dB at p: Vln I +5, Vln II +6, Vla +2, Vc 0, Cb -9 (-7 with Close 0.4), Fl -1, Ob -5, CA -1, Cl -1, BCl +1, Bn -2, Cbn +2, horns -4, trombones 0, tuba +2 with Close 0.45, timpani -7, harp -4 (c01-c05). These depend on the mic settings in section 12.
- Rimsky-Korsakov's resonance ratios worked as targets: in piano one wind equals one string section; in forte a string section is about +3 dB over one woodwind, a horn about two woodwinds, a trombone about two horns (Principles, "Comparison of resonance"). Measured result at both climaxes after c04: Vln I 3.2-3.5 dB over every single wind (c05 critic B); melody margins +4 to +6 dB at the climaxes after c05-c07.
- Accompaniment at the same printed dynamic as a melody needs a level cut (players do it); 3-7 dB cuts over spans worked (c02-c08). A cut set for a loud passage can bury a soft countermelody in the same span; check both (c04 critic B). A cut that ends at a climax should open over the last few beats (c06: role cuts opening over 4 qn), or the level arrives as a jump at the barline.
- Sample level varies by pitch at flat CC11 by 6-14 dB, on every articulation of the patch: Solo Horn F4 +5 to +7 (legato and Sus chords), G♭4 and A♭4 -5; Clarinet G5 +10, A♭5 -5; English Horn A4 +9; Basses A♭1 +6 to +8; Bassoon D♭3 +5; Violas pizz. F4 +10 (c06, c07, c08). Fit each note's body against its neighbours, average the residual per pitch, and apply a pitch trim to every articulation (or only to pizz. when only pizz. is hot). Horn 1 spread over one phrase went from 13 to 6.6 dB (c06).
- A flat pitch trim on a pitch whose note sags at the start deepens the sag (c08 critic A: horn F4 trimmed -5 dB went to 9.8-12.1 dB sag); give such trims an early and a body value (F4 early +1 / body -5 brought it to 6.6-7.7 dB; a larger early value is the next step). End pitch trims a few beats into very long notes (c08: at onset + 3 qn on notes over 4 qn).
- Find hot notes with a residual scan: per-note level against the track's CC11 fit; correct notes more than 5 dB over (c03-c08).
- A pp/ppp timpani roll should be 3-5 dB under the quietest sustained string section (c02 critic C target; reached in c04 except where a printed crescendo lifts it).
- Use A-weighting or K-weighting, not plain RMS, for balance between high and low instruments; RMS counted celli and basses a few dB higher than a listener hears them (c02 critic B, c04 critic C).

## 14. Low end

- The Basses KS Master carries almost all of the 40-90 Hz energy (c01: 99.7%; c04: within 0.1 dB of the master band). With default gains the master's 63 Hz third-octave band was +14.1 dB re 1 kHz against -6.2 in a recording (c00).
- Gain -9 dB on the basses brought 63 Hz to +4.7 (c01); a ReaEQ low shelf 90 Hz -7 dB plus a bell at 150 Hz +3 dB (1.4 oct) brought it to +1.1 (c04). Low shelf 70 Hz -4 dB on contrabassoon and tuba (c04). With the c05 mic changes 63 Hz went to -5.3, then -4.7 and -2.7 as soft and ff trims on the basses went up (c06, c07).
- Do not fix bass boom by lowering the basses' Close mic. Cb Close 0.94 -> 0.4, timpani Close/Main cuts and the new hall together took the 125-180 Hz band (loud frames, re 400-1000 Hz) from -9.5 to -15.5 dB against -3.7 in the reference (c05 per stem: Cb -4.7, timpani -7, Vc -3 dB). Cut the 40-90 Hz band with EQ and keep the 125-180 Hz body.
- A low-mid deficit at tutti can come from the voicing, not the mix. At f/ff the 125 Hz band (loud frames, re 1 kHz) was -9.8 against -0.7 in the reference while soft frames matched it; easing the celli's f/ff trims by 1-2 dB moved it from -10.3 to -10.4 dB (c08). In this score the climaxes leave 90-180 Hz to the basses' second harmonic and the timpani (c08 critic C, inferred).
- Upper-string Main-mic stems carry room rumble at 16-29 Hz, 34-40 dB under their level, which sums across instances (c05 critic C). High-pass at 40 Hz on upper strings, winds, horns and trombones, 30 Hz on celli/bassoons/bass clarinet/bass trombone, none on basses/contrabassoon/tuba/timpani/harp, put the master's 25-40 Hz band at -42.1 dB against -45.5 in the reference (c05; the filters' own effect was not isolated).

## 15. REAPER and bridge behaviour

- REAPER ignores `D_VOL` once a track has a volume envelope: the first c02 render lost every track gain (Vln I -7 dB, Cb +8 dB). Put the static gain inside the envelope and set `D_VOL` to 1.0 (c02).
- Writing a volume envelope by script: select the track, get "Volume" (create with action 40406 if missing), make sure it is active (`ACT 1` in the chunk), delete the old points, insert points with `ScaleToEnvelopeMode(GetEnvelopeScalingMode(env), amp)`, then `Envelope_SortPoints` (`build_reaper.py`).
- Three update paths, from cheapest: `--mix-only` (volume envelope and ReaEQ; pan stays centre once seats are in Opus), `--midi-only` (recreate each track's MIDI item and envelopes, keep the Opus instance; falls back to a full rebuild for a track whose generated state differs from the last one written), and a full rebuild (reloads patches; costs memory, section 11) (c01-c08).
- A tempo-map change needs every item recreated on the new map, but not the patches: write the tempo map first, then replace each track's MIDI item and envelopes (`--midi-only --tempo`, c08: 303 -> 323 tempo points, all 27 tracks, attack gate passed).
- ReaEQ by script: add with `TrackFX_AddByName(tr, "ReaEQ", false, -1)`, set band types with `TrackFX_SetNamedConfigParm(..., "BANDTYPEn", ...)` (0 low shelf, 8 bell, 4 high pass) and `BANDENABLEDn`; parameter scales are not linear, so set frequency/gain/bandwidth by binary search on the normalized value until `TrackFX_GetFormattedParamValue` shows the target (c04, c05).
- Render master plus every stem in one pass: `RENDER_SETTINGS 1`, `RENDER_BOUNDSFLAG 2` with the time selection set by `GetSet_LoopTimeRange`, pattern `$tracknumber_$track`, all tracks selected, action 42230 (c00-c08). Keep stem numbering stable by appending new tracks at the end (c01, c04).
- Timing: a 354 s render at 1x plus measurement takes about 5-6 minutes; the bridge call needs a long timeout (`--timeout 1800` used) and REAPER is blocked meanwhile (`render_cycle.py`).
- Tempo maps with many markers work: 300-323 square markers (0.25 qn steps inside rit./allargando spans plus caesuras) caused no problems (c03-c08). Writing MIDI with `MIDI_GetPPQPosFromProjQN` keeps notes on quarter-note positions.
- Crashes and freezes seen: Opus crashed on a locator-only zone (c00); the Mac froze during a second render in one session (c04; memory pressure inferred, section 11). After the reset REAPER reopened the saved project and a state read-back matched the build data exactly (c04), so save before every render (`render_cycle.py` does).

## 16. Measurement methods that worked

- Render one stem per track with the master, and measure the post-fader stems, not only the mix (c00-c08).
- Gate every render with an attack probe before judging anything else (`tools/probe_attacks.py`, run by `render_cycle.py`; c05-c08). The probe used: about ten isolated reference attacks (sound start = first 10 ms frame reaching max(peak - 20 dB, floor + 6 dB); limit 0.06 s for pizz., trombone and timpani, 0.15-0.20 s for soft strings), four held-note-to-tremolo arrivals (dip in the first 0.45 s against the 0.25 s before, limit 6 dB), and the opening voices (loudest 50 ms in the first 1.5 s above -70 dB). It separated good and bad renders cleanly: c04 failed 11 of 14, c05 1 of 14, c06 10 of 19, c07 and c08 0 of 19.
- The peak - 20 dB start measures when a note becomes audible, not when it arrives: Vln I passed at +0.04 s while its body (-6 dB) arrived 0.27 s late (c07 critic C). For soft entries add a body - 6 dB arrival check, and record memory (`metrics/memory.txt`) with every render.
- Per-note level: K-weighted, from onset + 80 ms to min(note end, onset + 1.5 s), paired with the CC11 at the onset; fit dB against CC11 per track (dB/CC and level at p/f/ff); scan residuals for hot notes and average them per pitch (c01-c08).
- Note shape: the first 0.3 s against the body (0.3-0.85 qn) finds sagging starts and bumps that a body-only level hides (c08).
- Per-bar and per-beat stem levels against the printed dynamics, the list of loudest stems per bar, and group power sums (melody / harmony / bass) for balance at climaxes (c01-c08). Bar level against the bar's loudest printed dynamic gives one number for macro dynamics: correlation 0.63 (c00), 0.89 (c02), 0.85 (c07), slope about 4 dB per dynamic step.
- Level across every hairpin, and the fall over the first 1-1.5 qn of each crescendo arrival note (c06, c08).
- Legato lag: time after the onset when energy at the new pitch's harmonics 1-4 exceeds the old pitch's (crossover), plus arrival within 6 dB; split by articulation, velocity and source pitch (c02-c07). An f0 trace every 20 ms against candidate pitches for fast figures and grace runs (c03).
- Join dips: lowest 20 ms window after a join against the 200 ms before (c01-c08).
- Entry timing: "first sound" (within 20 dB of the early peak) and "arrival" (within 6 dB) for entries after at least 0.5 qn of silence; list entries after a rest that never sound (c03, c05, c06). Compare median and p90 arrival across renders to spot engine lateness (c07: 0.060 / 0.307 s; c06 under memory pressure 0.102 / 0.425 s).
- Once notes are moved early for latency, keep the score onset in the data (`sq`) and measure against it; when the tempo map changes between cycles, convert each render with its own tempo map (c03-c08).
- Same-patch unisons: stem correlation in 0.5 s windows (c04).
- Space: per-stem L/R balance and correlation, side/mid ratio, tail balance after cutoffs, decay slopes (-5..-25 and -20..-40 dB) and the drop at 0.3/0.6/1.0 s after cutoffs (c01, c04, c05, c08).
- Spectrum: long-term third-octave bands re 1 kHz against a reference recording, split into loud frames (top 15%) and soft frames, and band shares per stem to find which track makes a band (c01-c08). The first reference was a 128 kb/s live MP3 of a different piece, so allow a few dB in the bass and use it for shape and decay, not exact targets.
- Loudness range (ffmpeg ebur128 LRA) against a recording of the same genre (c06: 25.4 LU against 21.8).
- State check: read notes, keyswitches, tempo markers, envelope points, widths and FX back from REAPER and compare with the build data before trusting a render after any crash or restart (c04, c06).

## 17. Pipeline lessons

- Keep everything that changes the result in scripts and config files (`mix.json`, `roles.json`, `note_trims.json`, `pitch_trims.json`, `early_fills.json`, `entry_leads.json`); a setting made only inside REAPER is lost on the next rebuild (BRIEF).
- Keep `parts.json` on score time; add the pre-roll, leads and other offsets only when writing to REAPER, and cut the pre-roll off the rendered files (c06).
- LilyPond extraction details that cost a cycle each: the slur stop event sits at the onset of the slur's last note, so test `start <= q <= stop` (c01); hairpins often have no stop event or a stop of the other kind, so close a hairpin at the next dynamic, the next hairpin or a rest of 2 qn or more (c01: a third of the printed dynamics were wrong, spans up to 268 qn); `arpeggio-event` needs its own listener (c04); `\removeWithTag #'part` can remove text that a second player on a shared staff needs (c05); a dynamic, mute or harp dynamic printed once on a shared staff may reach only one voice or one track (c05, c08).
- Hairpin rules that fixed measured errors (c06): an untargeted hairpin must not overshoot the next printed mark in its own direction; a decrescendo whose printed target is not below the current level falls 6 CC, and the mark at its end does not raise the level; "niente <" starts 12 CC below the target.
- Check the extracted dynamic curve against every printed mark and print any miss over 2 CC (c01).
- Change one family of things per cycle and keep before/after snapshots of tools and config; that is how the c04 vibrato change was cleared as a cause of late attacks (c05 critic A). Record the machine state (memory, compressed memory, other processes) with every render, since it changes render timing (c06-c08).

## 18. Where `guides/reaper-claude-scripting-guide.md` is wrong or incomplete

- §6.2 and §7 say patch loading inside Opus is not reachable from ReaScript. It is: write the patch JSON into the Opus state with `TrackFX_SetNamedConfigParm(tr, fx, "vst_chunk", ...)` (section 1 here).
- §6.3 says CC1 crossfades dynamic layers and CC11 shapes within a layer, and the §6.6 map uses `dynamics = 1, expression = 11, vibrato = 21`. In Hollywood Orchestra CC11 crossfades the dynamic layers and sets volume, CC1 is vibrato, and no CC21 vibrato control is mapped (section 3).
- §6.6 placeholder keyswitches (24-29, "range C0-B0") do not match the KS Masters: string keyswitches run from 24 up to 50, celli use 80-90, harp 21-35. Read them from the `.oib` files rather than from a screenshot (section 2).
- §6.3 "leave 50 ms of keyswitch lead": in practice put keyswitches in the preceding rest, and a keyswitch only works if its articulation row is loaded in the patch state (section 2).
- §10 "Keyswitches have no effect" omits the most common cause here: the articulation row is not loaded in the KS Master.
- §5 `R.tracks()` reports `vol_db` from `D_VOL`, which is wrong once a track has a volume envelope (section 15).
- §6.5 / `R.render` do not mention render speed or memory. Opus on an external sample drive needs 1x offline render (`RENDER_1X 1` in the `.rpp`, not settable through `GetSetProjectInfo`), a wait for sample loading, a silent pre-roll, a REAPER restart after patch reloads, and an attack-timing check (section 11). `RENDER_SETTINGS 1` with `RENDER_BOUNDSFLAG 2` gave master plus stems in one pass; the guide's `what = 3` was not used.
